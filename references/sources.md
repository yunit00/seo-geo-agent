# Источники данных и обходные пути

Все команды: `python3 <skill>/scripts/<имя>.py`, у каждой есть `--help`. Ключи лежат в `~/.config/seo-geo-agent/<домен>/secrets.env` (права только для владельца). Содержимое ключей в чат и в файлы не выводить. Как подключить каждый источник: [onboarding.md](onboarding.md).

## Содержание

1. Что какой источник отвечает
2. Команды
3. Отчеты без API (смотреть в браузере)
4. Известные сбои и что делать
5. Чего нет и как это закрыть

## 1. Что какой источник отвечает

| Вопрос | Источник | Оговорка |
|---|---|---|
| Сколько людей дошло до заявки или покупки | цели Метрики (`yandex.py conversions`), своя команда `leads_command`, слова владельца | цель считает действие на сайте, а не деньги; счетчик видит не всех |
| Сколько живых людей было на сайте и откуда | логи сервера (`logs.py`, `logs_weekly.py`, `periods.py`); без логов Метрика (`yandex.py summary`, `sources`) | заходы из мессенджеров и приложений приходят без реферера и лежат в «прямых»; Метрика теряет людей с блокировщиками и без согласия на куки |
| По каким запросам сайт показывает Яндекс | Вебмастер, `yandex.py queries` | только то, по чему уже показывают; окно всегда последние 14 дней с данными, отставание 3–4 дня |
| По каким запросам сайт показывает Google | Search Console, `gsc.py queries` | только то, по чему уже показывают; отставание около трех дней |
| Сколько спроса у запроса и кто стоит в выдаче | `wordstat.py` (Wordstat и поиск Яндекса через Yandex Search API) | платно; цифра это запросы со словами фразы, а не точная фраза; свежесть данных ограничена, см. ниже |
| На каком месте сайт по важным запросам | `positions.py` по списку `queries.txt` | платно; выдача нестабильна, скрипт берет медиану трех замеров |
| Что в индексе | `indexation.py`, `yandex.py indexing`, `gsc.py inspect <url>` | Google через URL Inspection (квота 2000 в сутки), Яндекс через Вебмастер |
| Что мешает роботам технически | `sitecheck.py` | видит сайт без JavaScript, как робот; скорость и цели не видит |
| Ходят ли AI-краулеры, есть ли переходы из нейросетей | `logs.py crawlers`, `logs.py ai`, `periods.py` | только при подключенных логах. Переходы считаются по рефереру и по `utm_source` (ChatGPT реферер обычно не передает); ChatGPT-User и Claude-User срабатывают и на ссылку, которую человек сам вставил в чат |
| Что написать и что доработать | `opportunities.py` | список с цифрами, не решение |

Wordstat по API, состояние на 24.11.2026 по документации Yandex Search API (<https://aistudio.yandex.ru/docs/ru/search-api/>):

- Цена за 1000 запросов с НДС: частотность (`topRequests`) 20 ₽, выдача синхронно 488 ₽ днем и 366 ₽ ночью (00:00–07:59 по Москве). Актуальные тарифы: <https://aistudio.yandex.ru/docs/ru/search-api/pricing>.
- Квоты: Wordstat 100 запросов в час, поиск 1 запрос в секунду.
- В документации стоит примечание, что в API Wordstat недоступна статистика за даты после 7 октября 2026 года; причина и срок не названы. Поэтому спрос из API читать как оценку порядка, а для свежих и сезонных тем сверять с интерфейсом wordstat.yandex.ru глазами. В режиме `учеба` перепроверять, снято ли ограничение.

## 2. Команды

```bash
setup.py status                                 # что подключено
sitecheck.py [адрес] [--pages 25] [пути...]     # технический аудит, ключи не нужны
snapshot.py [--pulse | --full] [--force]        # снимок всех подключенных источников

yandex.py check | summary | sources | pages | search | goals | conversions   [--days 30]
yandex.py queries | history | indexing
gsc.py check | summary | queries | pages | devices | sitemaps | inspect <url> | submit [карта]   [--days 28]
gsc_reach.py [--days 90] [--min-impr 15]        # запросы Google на 8–20 местах

wordstat.py top "пластиковые окна цена"         # частотность, хвосты, похожие запросы
wordstat.py batch --file queries.txt            # таблица частотности по списку
wordstat.py serp "как выбрать окна" [--n 50]    # выдача Яндекса и место сайта в ней
positions.py [--show]                           # места по списку queries.txt
opportunities.py [папка снимка] [--no-api]      # кандидаты для режима «совет»

logs.py sync | import <файлы> | report | pages | crawlers | ai   [--days 30]
logs_weekly.py                                  # динамика по неделям
periods.py [--no-gsc]                           # 7, 28, 90 дней против предыдущих

indexation.py [раздел] [--missing] [--google] [--yandex]
indexnow.py init | check | <пути> | --all
watch.py [--dry]                                # сторож без ИИ
```

Платные команды: `wordstat.py`, `positions.py`, `opportunities.py` (когда снимает новое). Ответы кэшируются на 30 дней. Перед большим запуском назвать владельцу число запросов.

Мобильная скорость: `npx lighthouse@12 <url> --only-categories=performance --form-factor=mobile --screenEmulation.mobile --throttling-method=simulate --output=json`. PageSpeed API без ключа быстро упирается в квоту.

## 3. Отчеты без API

Смотреть раз в месяц в браузере (сам владелец или агент через браузерный инструмент, только чтение). Цифры с экрана записывать в `adhoc_*.txt` рядом со снимком с датой.

| Отчет | Где | Что записать в замер |
|---|---|---|
| Видимость сайта в Алисе AI | Яндекс.Вебмастер, раздел «Эффективность» | доля присутствия, примеры запросов, сайты-конкуренты. История около трех месяцев, поэтому снимать каждый месяц |
| Генеративный ИИ в результатах Поиска | Search Console → Эффективность → Генеративный ИИ | показы за 28 дней и за 3 месяца, верхние 10 страниц. Кликов и запросов отчет не дает |
| AI Performance | Bing Webmaster Tools | цитирования и запросы; нужен подтвержденный сайт |
| Запросить индексирование | Search Console, строка «Проверка URL» сверху | квота около 10 адресов в сутки, в API кнопки нет |
| Диагностика сайта | Яндекс.Вебмастер → Диагностика | тексты критичных проблем: API отдает только их число |

В сессии браузера у Яндекса может быть несколько аккаунтов, и не каждый владеет сайтом. Какой нужен, записано в `profile.md`, раздел «Аккаунты». Входить, выходить, вводить пароли и капчи может только владелец.

## 4. Известные сбои

| Симптом | Причина | Что делать |
|---|---|---|
| `Invalid oauth_token` или 401 у Метрики и Вебмастера | токен отозван, протух (живет около года) или выпущен под другим аккаунтом | выпустить новый по `onboarding.md`, вписать в файл ключей, проверить `yandex.py check`. Если потерян сам аккаунт: сайт заново подтверждается в Вебмастере под другим аккаунтом (история данных привязана к сайту и сохраняется), счетчик Метрики переносится формой передачи счетчика из справки Метрики; это делает владелец |
| 403 `Required scope: COMMON` у Вебмастера при живой Метрике | токен выпущен без полного набора прав Вебмастера | перевыпустить, отметив все галочки Вебмастера |
| `yandex.py check` не находит счетчик или сайт | они живут в другом аккаунте Яндекса | выдать доступ аккаунту, под которым выпущен токен, или выпустить токен под аккаунтом-владельцем |
| Запросы Вебмастера пустые, хотя показы по дням есть | старый метод API `search-queries/popular` с 14.10.2026 отдает пустоту; скрипт уже ходит в новый (`query-analytics/list`) | окно у нового метода фиксированное, последние 14 дней с данными; `--days` не влияет. Если и он пуст (сайт только что добавлен, мало показов), так и писать в отчете: это отсутствие замера, а не ноль видимости. Проверить вторым путем: `yandex.py history` |
| Метрика отвечает 429 `quota_parallel_requests_by_uid` или 503 | у Метрики лимит одновременных запросов на пользователя, а в дни технических работ она отвечает минутами | `snapshot.py` пускает команды Метрики строго по очереди и повторяет временный отказ; в такой день снимок идет дольше. Сторож не считает разовый отказ тревогой |
| Отчет Метрики по внешним ссылкам отвечает 400 «query is too complicated» | длинный период по этой таблице ей не по силам | резать период на куски по 5 дней и складывать; фильтр писать точным совпадением |
| Таймаут API Вебмастера | сбой на стороне Яндекса | читать таблицы в интерфейсе Вебмастера через браузер и записать источник как «снято с экрана» |
| 403 у Search Console | сервисный аккаунт не добавлен в пользователи ресурса | Search Console → Настройки → Пользователи и разрешения → добавить адрес сервисного аккаунта |
| «Search Console API has not been used in project» | API не включен в проекте Google Cloud | включить Google Search Console API в библиотеке API проекта |
| `URL is unknown to Google` у свежей страницы | Google ее еще не обходил | не паниковать, запросить индексирование, проверить через две недели |
| 401 или 403 у `wordstat.py` | ключ не принят, нет роли `search-api.webSearch.user` или у ключа не та область действия | пересоздать ключ по `onboarding.md`; проверить, что платежный аккаунт активен |
| 429 у `wordstat.py` | исчерпана почасовая квота Wordstat | подождать час; уже снятое лежит в кэше |
| Место в выдаче Яндекса прыгает от запроса к запросу | поисковик пробует страницу на высоком месте и убирает | `positions.py` перепроверяет новое или сдвинувшееся место и берет медиану; разовый `wordstat.py serp` позицией не считать |
| В логах под именем ChatGPT-User или Perplexity-User просят `/.env` и подобное | сканеры уязвимостей подделывают имя агента | `periods.py` считает чтением только ответ 200 на настоящую страницу. `logs.py crawlers` этого не делает, его цифры чуть выше |
| `logs.py report` показывает ноль посетителей при живых запросах | статика сайта лежит на другом домене или CDN | в `site.json`: `"logs": {..., "require_assets": false}` |
| `logs.py sync` пишет «большая часть строк не разобрана» | формат лога не combined | попросить у хостинга формат combined или показать пример строки и поправить выражение `LINE` в `logs.py` |
| Сравнение 28 или 90 дней по логам неполное | архив короткий или в нем дыры | `periods.py` печатает покрытие, приводит суммы к числу суток и пишет «оценка»; при покрытии ниже четверти сравнения нет |
| Выдача Яндекса в браузере за капчей | автоматика | состав выдачи брать через `wordstat.py serp`; без ключа попросить владельца открыть 5–10 запросов руками |
| Bing `site:` через скрипт отдает мусор | Bing не отдает ботам выдачу | смотреть только в Bing Webmaster |

Новый сбой, которого здесь нет: разобраться, записать в `mistakes.md` рабочей папки, а если он не про конкретный сайт, предложить владельцу завести issue в репозитории скилла.

## 5. Чего нет и как закрыть

| Пробел | Чем закрыть | Что это даст |
|---|---|---|
| Bing и Copilot | подтвердить сайт в Bing Webmaster Tools (импорт из Search Console, пять минут, бесплатно) | индекс Bing и отчет AI Performance |
| Тренд цитирования в нейросетях | 30–50 фиксированных вопросов клиентов, по три прогона раз в месяц через API с веб-поиском (OpenAI, Yandex Search API с генеративным ответом) | ответы API не совпадают с интерфейсом, один прогон ничего не значит: читать только как тренд на уровне домена. Платно, собирается отдельным скриптом под сайт |
| Ежедневные позиции по большому списку | сторонний сервис съема позиций | `positions.py` рассчитан на десятки запросов раз в неделю, не на тысячи каждый день |
| Google Analytics | в скрипты не подключен | если сайт живет на GA, а не на Метрике: конверсии брать со слов владельца или своей командой `leads_command` |

Про сторонние MCP-серверы для Search Console, Метрики и Вебмастера: скиллу они не нужны, он ходит в официальные API напрямую и только на чтение. Перед установкой любого стороннего сервера проверить, какие права он запрашивает: токен с широкими правами открывает и рекламные кабинеты.
