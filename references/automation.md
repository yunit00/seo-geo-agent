# Расписание: что может работать само

Три вещи полезно поставить на расписание. Все они необязательны и включаются только с согласия владельца. Что включено, записать в `profile.md`, раздел «Расписание».

Скрипты работают на компьютере владельца: им нужны локальные ключи и архив логов. Компьютер спал в назначенное время: запуск пройдет позже или пропустится, в зависимости от планировщика. Выключен несколько дней: эти дни пропущены, а логи за пределами срока хранения хостинга потеряны.

## 1. Забор логов сервера (каждый день)

Нужен, только если подключены логи. Хостинги хранят их недолго, пропуск это потеря данных.

```bash
python3 <skill>/scripts/logs.py sync --site example.ru
```

## 2. Сторож (каждый день, без ИИ)

```bash
python3 <skill>/scripts/watch.py --site example.ru
```

Сам забирает логи (если настроены), снимает данные, проверяет грубые тревоги: источник не отвечает второй день, логи перестали приходить, поиск упал на треть, заявки упали вдвое, страница из `watch_urls` недоступна. Пока все в порядке, молчит. Тревоги пишет в `~/.config/seo-geo-agent/<домен>/watch/alerts.log`; агент читает этот файл в начале пульса.

Чтобы тревога приходила владельцу сразу, в `site.json` вписывается `alert_command`: любая команда, текст тревоги подставляется вместо `{text}` и лежит в переменной окружения `SEO_ALERT_TEXT`. Примеры:

```json
"alert_command": "osascript -e 'display notification (system attribute \"SEO_ALERT_TEXT\") with title \"SEO\"'"
```

```json
"alert_command": "curl -s -X POST https://api.telegram.org/bot$TG_BOT_TOKEN/sendMessage -d chat_id=$TG_CHAT_ID --data-urlencode text=\"$SEO_ALERT_TEXT\""
```

Во втором примере токен бота и идентификатор чата берутся из переменных окружения владельца, в `site.json` их не писать.

Если поставлен сторож, отдельный забор логов не нужен. Еженедельный съем позиций внутри сторожа выключен, потому что запросы платные; включается ключом `"watch_positions": true`.

Сначала прогнать вхолостую и показать владельцу, что сторож сказал бы: `watch.py --dry`.

## Как поставить на расписание

**macOS и Linux, cron.** `crontab -e`, строка (каждый день в 13:30):

```
30 13 * * * /usr/bin/python3 /полный/путь/к/skill/scripts/watch.py --site example.ru >> $HOME/.config/seo-geo-agent/example.ru/watch.log 2>&1
```

На macOS cron не запускает пропущенное во время сна. Если это важно, использовать launchd: файл `~/Library/LaunchAgents/<имя>.plist` с ключами `ProgramArguments` (python3, путь к скрипту, `--site`, домен), `StartCalendarInterval` (час и минута), `StandardOutPath` и `StandardErrorPath`, затем `launchctl bootstrap gui/$(id -u) <файл>`. Агент может создать файл сам и показать его владельцу перед включением. Выключить: `launchctl bootout gui/$(id -u)/<имя>`.

**Windows.** Планировщик заданий: действие `python`, аргументы `<путь>\scripts\watch.py --site example.ru`, триггер ежедневно.

## 3. Еженедельный пульс с агентом

Пульс требует ИИ, поэтому ставится не в cron, а задачей по расписанию в приложении, где работает агент (в Claude это раздел задач по расписанию; либо попросить агента «создай задачу по расписанию из automation.md»). Обычно понедельник, 10:00.

Текст задачи (подставить домен):

```
Сделай еженедельный пульс по поиску для сайта example.ru.

Как работать:
1. Загрузи скилл seo-geo-agent и прочитай profile.md и верхний блок status.md из рабочей папки сайта (путь покажет setup.py status).
2. Выполни режим «пульс» ровно по разделу «Пульс» скилла: снимок командой snapshot.py --pulse, сравнения из таблицы, ответ по шаблону пульса.
3. Сохрани текст ответа в файл pulse.md в папке пульса за сегодня.

Ограничения:
- Только чтение. Не правь сайт, рабочие документы и журнал гипотез. Ничего не публикуй. Браузер не открывай.
- Не читай и не выводи содержимое secrets.env и файла сервисного аккаунта.
- Если источник данных не ответил, назови его в строке «Не снято» с причиной и не заполняй пробел по памяти.
- Сравнивай одинаковое с одинаковым: неполную неделю с теми же днями прошлой, без сегодняшнего неполного дня.

Формат ответа: 6–9 строк по шаблону из раздела «Пульс», без таблиц. В конце одна строка «От тебя нужно», только если что-то ждет решения владельца.
```

## Чего не автоматизировать

- Правки на сайте и публикации: только в сессии с владельцем.
- Платные запросы большими пачками без названной владельцу цены.
- Все, что требует входа в аккаунт, капчи или согласия с условиями.
